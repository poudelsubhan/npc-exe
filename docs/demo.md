# Demo script

**Opening:** “Most NPCs can only use abilities their developer gave them. Pip has no build-bridge action. What happens if we give him a computer?”

Show the gap and click **Give Pip a computer**. Switch to theater mode if the projector needs a larger live view.

**While it works:** “This is a real Pine browser. He has the same drawing tool you can open yourself. We provide the goal and world constraints, but no route or click sequence.”

When the file returns, point to the bridge and Pip’s crossing. Open **Inspect the proof**.

**Reveal:** “His words don’t change the world. This downloaded file does. The game checks its identity, color, budget, obstacles and connectivity. Every step is on the accepted artifact.”

Place a rock on the old bridge, change to mint or rose, save, then send him again.

**Close:** “The story is written. The work between the story beats is performed. NPC.exe is a small example of characters that can create capabilities through tools outside their world.”

## Rehearsal and recovery

- Start both the game and tunnel before presenting. Confirm Pine is configured and the workshop is reachable.
- Keep the live challenge small. One newly placed rock is enough to demonstrate changed input and a different output.
- The local manual workshop is an explicit backup: say “I’m drawing this one myself to show the artifact contract.” Export, then use Import blueprint.
- If Pine fails, show the real error and Retry. Do not present manual work or an old receipt as the current live run.
- Do not promise a fixed finish time. The two successful local runs took 27.6 and 38.9 seconds, but these are observations, not a timing guarantee.
- The audience can pick any water cell for a rock. Impossible scenes are rejected before a new paid run.
- Ctrl+C on the game cancels its active run and releases compute. Check the Pine console if cleanup reports unconfirmed.
